# Reflection

One important design decision was to use Amazon Bedrock AgentCore to connect the customer support agent to managed services such as Gateway, Memory, Knowledge Base, Browser, and Code Interpreter. This keeps the agent architecture modular while allowing each capability to be validated independently. I also used the Gateway layer to expose order and refund operations rather than connecting the agent directly to the backend services.

The main challenge I encountered was getting the Browser capability working in the deployed AgentCore runtime. The agent initially failed because the runtime role did not have permission to start the managed browser session. After identifying the `StartBrowserSession` authorization error in CloudWatch, I added the required Browser permissions for the system browser resource. I then encountered a Python 3.14 asynchronous runtime issue involving `nest_asyncio` and an AnyIO weak-reference error. I worked around this by preventing the browser library from reapplying `nest_asyncio` during browser execution. After redeployment, the Browser test successfully accessed Amazon.com and returned the page title.

A production consideration is security and observability. The project currently uses an educational Gateway configuration without authentication, so a production implementation should use authenticated access and least-privilege IAM permissions. I also added CloudWatch monitoring with an ERROR metric filter and an alarm for more than five errors in a five-minute period. This provides a basic mechanism for detecting runtime failures and supports operational monitoring.
